# Инструменты для решения заданий по стеганографии

## Введение

Стеганография — это сокрытие информации внутри другого объекта: изображения, аудиозаписи, документа или архива. В отличие от криптографии, которая скрывает смысл сообщения, стеганография старается скрыть сам факт существования сообщения.

При решении CTF-заданий полезно двигаться от простых проверок к более сложным:

1. определить реальный тип файла;
2. изучить его метаданные;
3. найти читаемые строки;
4. проверить файл на встроенные или дописанные данные;
5. попробовать специализированные инструменты;
6. при необходимости изучить байты файла вручную.

Все команды ниже следует выполнять в директории с распакованными файлами заданий:

```bash
cd ~/les-3
ls -la
```

---

## Установка инструментов в Kali Linux

Обновить сведения о пакетах и установить основной набор утилит можно командами:

```bash
sudo apt update
sudo apt install libimage-exiftool-perl poppler-utils binwalk p7zip-full foremost steghide hexedit
```

Назначение пакетов:

- `libimage-exiftool-perl` устанавливает команду `exiftool`;
- `poppler-utils` содержит `pdfinfo` и другие утилиты для PDF;
- `binwalk` ищет известные сигнатуры внутри файлов;
- `p7zip-full` предоставляет команду `7z`;
- `foremost` извлекает файлы по их сигнатурам;
- `steghide` работает со скрытыми вложениями в JPEG, BMP, WAV и AU;
- `hexedit` позволяет просматривать файл в шестнадцатеричном виде.

Проверить доступность программ:

```bash
exiftool -ver
pdfinfo -v
binwalk --help
7z --help
foremost -V
steghide --version
```

## Команды `file` и `ls`: первичный осмотр

### `ls`

Команда `ls` показывает файлы в директории. Ключ `-l` добавляет размер, права доступа и дату изменения, а `-h` выводит размер в удобном виде:

```bash
ls -lh
```

Необычно большой размер изображения или короткой аудиозаписи может указывать на дополнительные данные внутри файла.

---

### `file`

Расширение файла не гарантирует, что перед нами действительно изображение, PDF или аудиозапись. Команда `file` определяет формат по сигнатуре содержимого:

```bash
file image.jpg
file document.pdf
file image.png
file audio.wav
```

Сразу проверить все файлы в текущей директории можно так:

```bash
file *
```

Следует сравнить расширение с результатом команды и обратить внимание на дополнительные сведения: разрешение изображения, версию PDF, параметры аудио и упоминание архивных данных.

## `exiftool`: просмотр метаданных

Метаданные — это служебные сведения о файле. Они могут содержать имя автора, комментарий, описание, название документа, модель камеры, координаты и время создания. В CTF в одно из этих полей часто помещают подсказку или флаг.

Просмотр всех доступных метаданных:

```bash
exiftool image.jpg
exiftool document.pdf
```

Для вывода названий полей в техническом формате используется ключ `-s`:

```bash
exiftool -s image.jpg
```

Для просмотра только выбранных полей можно указать их явно:

```bash
exiftool -Comment -Description -Title -Subject -Artist image.jpg
```

Поиск интересных строк без учёта регистра:

```bash
exiftool image.jpg | grep -Ei 'comment|description|title|subject|author|flag|ctf'
```

При анализе важно просматривать не только привычные EXIF-поля изображения. `exiftool` также читает IPTC, XMP и метаданные PDF.

Полезные параметры:

- `-a` — показать повторяющиеся поля;
- `-u` — показать неизвестные поля;
- `-g1` — сгруппировать данные по типу метаданных.

Расширенный просмотр:

```bash
exiftool -a -u -g1 protected.jpg
```

---

## `pdfinfo`: свойства PDF-документа

`pdfinfo` показывает основные сведения о PDF: заголовок, тему, автора, программу-создатель, даты, число страниц и размер листа.

```bash
pdfinfo document.pdf
```

Наиболее интересны поля:

- `Title` — название;
- `Subject` — тема документа;
- `Author` — автор;
- `Keywords` — ключевые слова;
- `Creator` и `Producer` — программы, которыми создан PDF.

Если нужное поле не отображается в `pdfinfo`, следует дополнительно использовать `exiftool`: часть сведений может храниться в XMP-метаданных.

```bash
exiftool -a -u -g1 document.pdf
```

## `strings`: поиск читаемого текста

Файлы изображений и аудиозаписей в основном состоят из двоичных данных, но внутри них могут встречаться читаемые строки. Утилита `strings` извлекает такие последовательности.

```bash
strings image.png
```

Ключ `-a` заставляет просматривать весь файл, а `-n` задаёт минимальную длину строки:

```bash
strings -a -n 6 image.png
```

Результат можно отфильтровать:

```bash
strings -a image.png | grep -Ei 'ctf|flag|pass|secret|zip'
```

Для просмотра последних строк удобно использовать `tail`:

```bash
strings -a image.png | tail -n 30
```

`strings` не извлекает вложение автоматически. Он помогает обнаружить имена файлов, фрагменты текста и признаки архива, после чего следует применить `binwalk` или `7z`.

## `binwalk`: поиск данных внутри файла

`binwalk` ищет внутри файла сигнатуры известных форматов. Например, в конце обычного изображения может находиться ZIP-архив, а после данных WAV — архив `tar.gz`.

Проверка файла:

```bash
binwalk image.png
binwalk audio.wav
```

Основные столбцы результата:

- `DECIMAL` — смещение в байтах от начала файла;
- `HEXADECIMAL` — то же смещение в шестнадцатеричном виде;
- `DESCRIPTION` — предполагаемый тип найденных данных.

Если обнаруженная сигнатура находится не в начале файла, это может означать наличие вложения или данных, дописанных после основного контейнера.

Автоматическое извлечение:

```bash
binwalk -e image.png
```

Некоторые версии `binwalk` требуют разрешить запуск внешних распаковщиков от имени текущего пользователя:

```bash
sudo binwalk -e --run-as=root image.png
```

После извлечения рядом обычно появляется директория с именем наподобие `_image.png.extracted`. Её содержимое нужно осмотреть:

```bash
find _image.png.extracted -maxdepth 2 -type f -print
file _image.png.extracted/*
```

## `7z`: просмотр и извлечение архивов

Программа `7z` умеет определять и открывать многие архивные форматы. Иногда она может найти архив, даже если тот дописан к изображению или аудиофайлу.

Посмотреть содержимое без извлечения:

```bash
7z l image.png
7z l audio.wav
```

Извлечь найденные данные в отдельную директорию:

```bash
mkdir extracted_data
7z x image.png -oextracted_data
```

После извлечения:

```bash
find extracted_data -type f -maxdepth 2 -print
file extracted_data/*
```

Предупреждение о данных до или после архива в учебном задании не всегда означает ошибку: это может быть указанием на объединение двух файлов.

---

## `foremost`: извлечение по сигнатурам

`foremost` выполняет file carving — ищет начало и конец известных типов файлов и сохраняет найденные объекты. Инструмент полезен, если `binwalk` обнаружил данные, но не смог их извлечь.

```bash
foremost -i audio.wav -o foremost_output
```

Здесь:

- `-i` задаёт исследуемый файл;
- `-o` задаёт новую директорию для результатов.

Просмотр результата:

```bash
find foremost_output -type f -print
```

Важно: директория вывода не должна существовать перед запуском или должна быть пустой. `foremost` особенно хорошо работает с распространёнными изображениями и документами, но не всегда распознаёт каждый тип архива.

## Шестнадцатеричный редактор

Hex-редактор показывает реальные байты файла. Слева обычно отображается смещение, в центре — байты в шестнадцатеричном виде, справа — их текстовое представление.

Открыть файл в терминальном редакторе:

```bash
hexedit image.png
```

В `hexedit` можно искать текст клавишей `/`. Полезно искать обозначения форматов и имена файлов.

Часто встречающиеся сигнатуры:

| Формат | Сигнатура в hex | Текстовое представление |
|---|---|---|
| JPEG | `FF D8 FF` | — |
| PNG | `89 50 4E 47 0D 0A 1A 0A` | `.PNG....` |
| PDF | `25 50 44 46` | `%PDF` |
| ZIP | `50 4B 03 04` | `PK..` |
| GZIP | `1F 8B` | — |
| WAV | начинается с `52 49 46 46`, далее содержит `57 41 56 45` | `RIFF....WAVE` |

У PNG формальный конец обозначается блоком `IEND`. Если после него находятся значительные данные и новая сигнатура, это повод проверить файл на вложение.

Hex-редактор полезен для понимания структуры, однако вручную копировать байты обычно не требуется: найденное смещение можно передать утилите `dd`.

Например, если `binwalk` сообщил, что вложение начинается со смещения `12345`:

```bash
dd if=image.png of=embedded.bin bs=1 skip=12345 status=progress
file embedded.bin
```

Значение `12345` здесь является примером; при решении нужно использовать смещение из собственного вывода `binwalk`.

## `steghide`: скрытые вложения в JPEG и WAV

`steghide` встраивает данные внутрь JPEG, BMP, WAV или AU. Содержимое может быть защищено парольной фразой. Обычный просмотр изображения не показывает наличие вложения.

Получить сведения о контейнере:

```bash
steghide info container.jpg
```

Программа может запросить подтверждение просмотра сведений и парольную фразу. Если по условию пароль отсутствует, достаточно нажать Enter или явно передать пустую строку.

Извлечение с пустой парольной фразой:

```bash
mkdir extracted_open
cd extracted_open
steghide extract -sf ../container.jpg -p ''
```

После извлечения необходимо вернуться в исходную директорию и проверить результат:

```bash
ls -la
file *
cd ..
```

Извлечение с известной парольной фразой:

```bash
mkdir extracted_protected
cd extracted_protected
steghide extract -sf ../protected.jpg -p '<парольная_фраза>'
```

Пароль в CTF-задании не обязательно требуется перебирать. Он может находиться в описании, имени файла, метаданных или визуальном содержимом изображения. Поэтому перед перебором следует внимательно изучить условие и выполнить:

```bash
exiftool -a -u -g1 protected.jpg
```

## Audacity и Sonic Visualiser

Аудиофайл можно открыть в Audacity или Sonic Visualiser и изучить его форму сигнала и спектрограмму. Это полезно, когда информация скрыта в частотах, паузах, отдельных каналах или необычных звуках.

В Audacity спектрограмма включается через меню дорожки: `Waveform` → `Spectrogram`. После этого стоит изменить масштаб и параметры спектрограммы.

Однако не каждое аудиозадание требует анализа звука. Если файл короткий, но имеет необычно большой размер, сначала следует проверить его командами:

```bash
file audio.wav
ls -lh audio.wav
binwalk audio.wav
7z l audio.wav
```

Так можно отличить данные, спрятанные в спектре, от архива, дописанного после WAV-контейнера.

Пример: https://blog.welcomethrill.house/2018/04/the-audacity-of-some-ctfs.html

## Универсальный алгоритм анализа файла

Для большинства начальных заданий можно применять следующую последовательность:

```bash
ls -lh <файл>
file <файл>
exiftool -a -u -g1 <файл>
strings -a <файл> | tail -n 30
binwalk <файл>
7z l <файл>
```

Далее инструмент выбирается по результатам:

- найдены интересные метаданные — изучить их через `exiftool` или `pdfinfo`;
- найдена сигнатура архива — использовать `binwalk -e`, `7z x` или `dd`;
- файл подходит для `steghide` — выполнить `steghide info` и попробовать извлечение;
- автоматические инструменты ничего не показали — открыть файл в hex-редакторе;
- подозрителен сам звук — изучить спектрограмму.

## Выбор инструмента по признакам файла

| Наблюдение | Что проверить | Подходящие инструменты |
|---|---|---|
| В условии упомянуты автор, свойства или комментарий | служебные поля и метаданные | `exiftool`, `pdfinfo` |
| Файл заметно больше ожидаемого | дополнительные или дописанные данные | `binwalk`, `7z`, `foremost` |
| В двоичном файле могут находиться читаемые подсказки | текстовые последовательности | `strings`, `grep` |
| Автоматический анализ обнаружил сигнатуру по ненулевому смещению | вложенный объект | `binwalk -e`, `7z x`, `dd` |
| JPEG или WAV выглядит нормально, но условие говорит о скрытом содержимом | стегоконтейнер | `steghide` |
| В аудио слышны или видны необычные элементы | форма сигнала и частотный спектр | Audacity, Sonic Visualiser |
| Автоматические средства не дали результата | структура и сигнатуры файла вручную | `hexedit` |

Эта таблица определяет направление анализа, но не заменяет изучение условия. Формулировка и необычные слова часто подсказывают, какой инструмент следует применить первым.

## Частые ошибки

1. **Ориентироваться только на расширение.** Реальный формат всегда стоит проверить командой `file`.
2. **Сразу запускать перебор пароля.** Сначала нужно изучить условие, метаданные и содержимое файла.
3. **Открывать двоичный файл обычным текстовым редактором.** Для этого предназначены `strings` и hex-редактор.
4. **Извлекать файлы в ту же директорию.** Лучше создавать отдельную папку для каждого результата.
5. **Игнорировать смещение в выводе `binwalk`.** Ненулевое смещение показывает, где внутри контейнера начинается другой объект.
6. **Считать предупреждение `7z` ошибкой.** При анализе объединённых файлов предупреждение о дополнительных данных может быть ожидаемым.
7. **Запускать найденные файлы.** Сначала следует определить их тип через `file`; неизвестные исполняемые файлы запускать не нужно.

---

## Итог

Основной навык при решении заданий по стеганографии — не знание одной специальной команды, а последовательный анализ. Сначала используются безопасные обзорные инструменты (`file`, `exiftool`, `strings`), затем средства обнаружения и извлечения (`binwalk`, `7z`, `foremost`, `steghide`), а ручной анализ в hex-редакторе помогает проверить гипотезу и понять устройство файла.
